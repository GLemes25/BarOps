"Como um Engenheiro Frontend Sênior, corrija os bugs de Timezone Offset no EventForm que estão fazendo a data ficar em branco na edição e retroceder um dia no banco de dados.

Execute rigorosamente os seguintes passos:

Correção da Exibição (Data em branco):

O <Input type="date"> exige estritamente o formato YYYY-MM-DD.

Atualize a inicialização do defaultValues.date. Se record?.date existir, faça um parse seguro que garanta o formato YYYY-MM-DD no fuso horário local (evitando que new Date().toISOString() retroceda um dia dependendo do horário em que for aberto).

Uma abordagem simples e eficaz se record.date for uma string ISO ou timestamp é extrair os 10 primeiros caracteres, ou usar uma formatação local segura (ex: separando por 'T' caso seja ISO, ou montando a string manualmente).

Correção do Salvamento (Retrocesso de 1 dia):

Na função onSubmit, antes de enviar os dados para o banco, proteja a string da data.

Se o usuário preencheu 2026-06-20, modifique values.date para que ele contenha um horário neutro. Adicione o sufixo T12:00:00 (meio-dia) à string da data antes de enviá-la no payload.

Isso garante que, independentemente da conversão de UTC para LocalTime que o Drizzle/Postgres faça nos bastidores, a data permanecerá no mesmo dia calendário.

Não adicione comentários explicativos no código. Mantenha a tipagem e as validações do Zod intactas."
